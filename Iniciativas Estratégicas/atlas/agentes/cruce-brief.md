# Encargo: cruzar un concepto compartido contra la definición de su dueño

You check whether a 28-document Spanish policy corpus (the **¡BASTA!** PLANes) is consistent with
itself about a handful of named concepts. Your prompt gives you one dossier file and a group number `N`.

Paths below are relative to the repository root; run commands from there.

## Goal

Each concept in your dossier is **owned** by one PLAN (which defines it) and **used** by others.
Editors keep changing the owner's definition while the users keep describing the old version: a
different amount, a different meaning for the sigla, a different body in charge, a feature the owner
never gave it. We want every place where **a user PLAN states something about the concept that the
owner's text contradicts**, with both lines quoted, so an editor can go and reconcile them.

Precision beats recall. A false alarm costs an editor ten minutes and teaches them to ignore the
list. Three solid findings are worth more than fifteen doubtful ones. **Zero findings for a concept
is a normal, expected answer.**

## Input

The dossier (generated by `atlas/construir.mjs --dossiers`) has, per concept:

- `## Cómo lo define su dueño` — excerpts `PLANX:LINE: text` from the owner document.
- `## Cómo lo usan los otros` — excerpts `PLANY:LINE: text` from every other PLAN that names it.

Excerpts are windows of ~600 characters around the mention, not whole lines. The full documents are at
`Iniciativas Estratégicas/<CODE>_Argentina_ES.md`.
**Before reporting a finding, open both lines** with the Read tool (`offset` = line number, `limit` ≈ 3,
or a wider window if you need context) and confirm the conflict survives reading the whole paragraph.
An excerpt can hide a «no», an «hasta», or a different year.

## What counts as a finding

- **Number**: amount, percentage, count, date or term differs (owner says 0,05% of GDP, user says 0,07%).
- **Name**: the sigla is expanded differently, or the same thing carries two names.
- **Who**: a different body runs it, funds it, appoints it or owns it.
- **What**: the user attributes a function, power or component that the owner's text denies or does
  not have, or relies on something the owner explicitly defers or deletes.
- **Status**: the user treats as existing/operative what the owner says is deferred, piloted or conditional
  (or the reverse).

## What does NOT count

- Paraphrase, summary, less detail, or more detail that fits the owner's definition.
- A user describing its own use of the concept (what it plugs into it), as long as it does not
  misdescribe the concept itself.
- Ranges that overlap because one side rounds («~USD 200M» vs «USD 180–220M»).
- Differences between two lines **of the owner document itself** (another pass handles those).
- Different years or scenarios clearly labelled as such on both sides.
- Anything you cannot support with a literal quote from each side.

## Output — exactly one file

`Iniciativas Estratégicas/atlas/lecturas/cruces-<N>.json`

```json
{
  "grupo": 3,
  "revisados": ["Empresa Bastarda", "ANCE", "…every concept name in your dossier…"],
  "cruces": [
    {
      "concepto": "AMCC",
      "tipo": "numero",
      "dueno": "PLANMESA",
      "lineaDueno": 497,
      "citaDueno": "verbatim substring of that line of the owner, 10–200 chars",
      "otro": "PLANJUS",
      "lineaOtro": 1033,
      "citaOtro": "verbatim substring of that line of the other PLAN, 10–200 chars",
      "que": "En español, una oración con los dos valores: «PLANMESA fija el presupuesto de la AMCC en 0,05% del PBI; PLANJUS lo da en 0,07%»."
    }
  ]
}
```

- `tipo`: `numero` · `nombre` · `quien` · `que` · `estado`.
- `dueno` is always the owner PLAN named in the dossier; `otro` is the user PLAN.
- `citaDueno` / `citaOtro` are **verbatim substrings of that single line of the real file** (copy from
  the Read output, not from the dossier excerpt, which normalises whitespace). Keep `**`, backticks,
  accents. No ellipsis. A build script checks them literally and silently drops any cruce whose
  quotes do not match, so a careless quote throws your finding away.
- `que` in Spanish, plain, with the two values side by side. No adjectives, no advice.
- At most 4 cruces per concept: keep the most consequential.
- Write ¡BASTA! with both marks if you write it.

## Scope

IN: the one JSON file. **DO NOT edit any other file.** Do not fix the documents.

## Self-check before you return

```bash
node -e '
const fs=require("fs"),T="Iniciativas Estratégicas/";const n=s=>String(s).replace(/\s+/g," ").trim();
const d=JSON.parse(fs.readFileSync(T+"atlas/lecturas/cruces-<N>.json","utf8"));let bad=0;
for(const c of d.cruces){for(const [p,l,q] of [[c.dueno,c.lineaDueno,c.citaDueno],[c.otro,c.lineaOtro,c.citaOtro]]){
const L=fs.readFileSync(T+p+"_Argentina_ES.md","utf8").split("\n");if(!n(L[l-1]||"").includes(n(q))){bad++;console.log("NO COINCIDE",c.concepto,p+":"+l,"«"+n(q).slice(0,60)+"»")}}}
console.log(d.cruces.length+" cruces, "+bad+" citas que no coinciden")'
```

Replace `<N>` with your group number. It must end with `0 citas que no coinciden`. Fix or delete
until it does.

## Return (≤120 words)

1. The self-check's last line.
2. One line per concept: its name and how many cruces you kept (0 is fine).
3. Anything that blocked you. STOP and report instead of guessing if the dossier file is missing.
